# V93 시즌내 복원 피처의 Form 모델 내부 통합 검증

## 1. 가설

V92는 복원 신호를 **완성된 예측에 더하는 단일 선형항**으로 썼다. 그 항은 전역
기울기 하나만 표현할 수 있고, 복원 피처 18개 중 투수 success 델타 1개만 사용했다.

Form HGB가 복원된 비율을 직접 소비하면 두 가지가 가능해진다.

1. 카운트·이닝·주자·표본 수와의 **상호작용**을 학습할 수 있다.
2. 오염된 통산 비율을 **보정**하는 것이 아니라 **대체**할 수 있다.

또한 V92가 쓰지 않은 신호가 남아 있다. 특히 `middle_rate`는 공식 실패 정의 3가지 중
하나("스트라이크존 가운데")에 직결되는데 시즌내 버전이 미사용이었다.

## 2. 변경점

V38 gentle_500 설정(`max_leaf=15, min_samples=200, l2=20, lr=0.03, iter=500`),
V17 트리·Logistic 레이어, Context HGB, 블렌드 가중치 `0.55/0.32/0.13`,
보정 구조를 모두 고정했다. **Form 피처 집합에만 복원 피처 18개를 추가**했다.

- Form 피처 수: `87 → 105`
- 추가 피처: 투수 5개 비율의 시즌내값·통산 대비 델타(10개), 타자 2개 비율의
  시즌내값·델타(4개), 시즌내 로그 표본 수 2개, 투수 신뢰도, 마지막 등장 이후 시즌 수
- 새 Form OOF로 **전역 shift와 카운트/투수 보정 lookup을 재산출**했다
  (`-0.011288 → -0.010595`)

학습 행의 복원 피처는 각 시즌마다 직전 시즌 종료 anchor로 만들었다. 이는 2025 평가
행이 2019–2024 학습 데이터에 대해 갖는 관계와 동일하다.

### 설계 판단 3가지

**(1) 2019을 결측으로 남기고 학습하는 편이 낫다.** 2019은 anchor가 없어 복원 피처가
전부 결측이지만, 제외하면 2024 gain이 `+37.0 → +25.4`점으로 떨어진다. 24만 행을
버리는 손실이 결측 블록의 손실보다 크다. HGB의 native 결측 처리로 충분하다.

**(2) Form 레이어 전체 대체가 절반 대체보다 낫다.** 같은 조건에서 `+37.0` vs `+22.1`.

**(3) V92의 post-hoc 드리프트 항을 반드시 유지해야 한다.** 이것이 가장 중요한 발견이다.
제거하면(`드리프트0.00`) 2024 gain이 `+37.0 → +28.5`점으로 줄어드는 데 그치지 않고,
**블록 승률이 `100% → 70%`, 최악 블록이 `+2.20e-06 → -1.10e-04`로 부호가 뒤집힌다.**

즉 모델 내부 피처와 전역 선형항은 **중복이 아니라 상보적**이다. 트리는 복원값을
상황과 상호작용시키는 데는 뛰어나지만, **리그 수준 이동 자체를 외삽하지는 못한다**
(`season`이 피처로 들어가 있고 2025는 학습 범위 밖이다). 전역 항이 그 역할을 맡는다.
이 관찰은 V94(`season` 제거·리그 오프셋 외삽)의 직접적인 근거가 된다.

## 8. 1차 제출 실패와 원인 — 직렬화 호환성

V93 1차 제출이 평가 서버에서 다음 오류로 실패했다. 모델 품질과 무관한 환경 문제다.

```
ValueError: <class 'numpy.random._pcg64.PCG64'> is not a known BitGenerator module.
(File: /app/script.py, Line: 150)
```

### 원인

로컬 `lgaimers` 환경의 numpy가 **2.4.6**인데 평가 서버는 **1.26.4**다. numpy 2.x는
`np.random.Generator`를 **클래스 참조**로 pickle하지만 numpy 1.x는 **문자열 이름**만
해석할 수 있어 로드가 깨진다. 원인 객체는
`HistGradientBoostingClassifier._feature_subsample_rng`이며, fit 전용이고 추론에는
쓰이지 않지만 pickle에 함께 저장된다.

서버와 동일한 버전의 환경(`lgaimers_server`)을 만들어 로컬에서 오류를 재현했다.

| 아티팩트 | pickle 방식 | 서버 로드 |
|---|---|:---:|
| `v6_ensemble.joblib` | numpy 1 (문자열) | OK |
| `v17_logistic_model.joblib` | RNG 없음 | OK |
| `v38_feature_models.joblib` | numpy 1 (문자열) | OK |
| `v41_calibration.joblib` | RNG 없음 | OK |
| `v92_inseason_anchor.joblib` | RNG 없음 | OK |
| `v93_calibration.joblib` | RNG 없음 | OK |
| **`v93_feature_models.joblib`** | **numpy 2 (클래스)** | **FAIL** |

7개 중 1개만 실패했다. V41·V92가 무사했던 이유는 기존 파일을 **재사용만** 했기
때문이고, V93에서 처음으로 모델을 새로 학습해 새로 저장했다.
**V92는 fallback으로 여전히 안전함을 확인했다.**

## 10. 환산 계수 정정 — `1.475배`가 아니라 누적 `0.94배`

V92 한 점만으로 추정한 `1.475배`는 **과대추정이었다.** 두 점이 확보된 지금의 실측이다.

| 버전 | 로컬 2024 gain | 로컬 환산 | 실제 상승 | 실제/로컬 |
|---|---:|---:|---:|---:|
| V92 | `4.0928e-05` | `16.4점` | `+24.1653` | **`1.476`** |
| V93 | `9.2450e-05` | `37.0점` | `+26.2030` | **`0.709`** |
| **누적** | `1.3338e-04` | `53.4점` | **`+50.3683`** | **`0.944`** |

단계별 비율은 `0.71`과 `1.48`로 크게 흔들리지만, **누적으로 보면 로컬 2024 개발 구간
gain이 실제 리더보드 상승과 거의 1:1(`0.94`)로 대응한다.** 단일 후보의 비율을
계수로 쓰면 안 되고, 누적 기준 `0.94`를 사용한다.

V93의 비율이 1보다 낮은 이유는 V92와 **같은 정보원**을 공유하기 때문일 가능성이 높다.
두 후보 모두 시즌내 복원 신호에 기반하므로, 로컬에서 측정한 V93의 순증분 일부가
2025에서는 V92가 이미 포착한 부분과 겹친다.
