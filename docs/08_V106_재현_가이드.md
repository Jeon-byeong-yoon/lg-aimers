# V106 재현 가이드 (Phase 3 코드 제출용)

> 대상 모델: `submit_v106.zip`, Public Score **`973.0643764994`**
> 시작 기준선: V41 `900.7385360187` → 누적 개선 **`+72.3258`**

Phase 3 진출은 Private 순위만으로 결정되지 않는다. `docs/04` 3절에 따라 **Private
재현용 학습 코드**와 솔루션 PPT를 제출해 검증을 통과해야 한다. V106을 만든 작업은
100여 개의 실험 스크립트에 흩어져 있으므로, 이 문서는 **V106이 실제로 의존하는
단계만** 순서대로 정리한다.

## 1. 사용 데이터

주최 측 공식 파일 두 개만 사용한다. 외부 데이터와 API는 사용하지 않았다.

| 파일 | 행 수 | 용도 |
|---|---:|---|
| `공모전 dataset/open/data/train.csv` | `1,475,092` | 학습 및 시간순 검증 |

## 2. 실행 환경

### 2.1 반드시 지킬 것 — 제출 아티팩트는 서버 미러 환경에서 저장한다

평가 서버는 numpy `1.26.4`를 쓴다. numpy 2.x가 저장한 pickle은
`HistGradientBoostingClassifier._feature_subsample_rng`(`np.random.Generator`)를
**클래스 참조**로 담는데 numpy 1.x는 **문자열 이름**만 해석하므로 로드가 깨진다.

```
ValueError: <class 'numpy.random._pcg64.PCG64'> is not a known BitGenerator module.
```

이 오류로 V93 1차 제출이 실패해 일일 제출 기회 1회를 잃었다. `docs/05` 7절에 따라
`script.py` 실행 후 발생하는 오류는 일일 횟수에 반영된다.

## 5. 모델 구조

최종 예측은 세 성분의 가중 합에 보정과 드리프트 항을 더한 값이다.

```
v17      = 0.95 * (네 트리 모델 가중합) + 0.05 * 정규화 Logistic
예측      = 0.19 * v17 + 0.64 * Form HGB + 0.17 * Context HGB
         + 전역 shift
         + 0.75 * 카운트 보정 + 0.25 * (투수 x 카운트) 보정
         + 0.10 * 시즌내 드리프트 항
예측      = clip(예측, 0, 1)
```

### 5.1 V17 트리 레이어 내부 가중치

| 성분 | 가중치 | 피처 |
|---|---:|---|
| ExtraTrees | `0.294836` | 공식 as-of + 행 단위 파생 |
| Trackman HGB | `0.234446` | 위 + 상황별 Trackman 집계 |
| Target-encoded HGB | `0.116176` | 위 + 투수/타자 Target Encoding |
| Hierarchical HGB | `0.354543` | 위 + 투수×타자 계층 인코딩 |

### 5.2 Form HGB (비중 `0.64`, 최대 성분)

`max_leaf_nodes=15`, `min_samples_leaf=200`, `l2_regularization=20`,
`learning_rate=0.03`, `max_iter=500`, `random_state=42`. 피처 105개.

이 설정은 V38에서 선택되었고 V97·V107에서 용량을 **양방향으로** 재검증해
최적임을 확인했다.

### 5.3 Context HGB (비중 `0.17`)

`hist_gbdt_pipeline` 기본 설정(`max_iter=200`, `learning_rate=0.06`,
`max_leaf_nodes=31`, `min_samples_leaf=100`, `l2_regularization=5`).
`hte_pitcher_batter_*` 3개를 제외한다(V31).

### 5.4 시즌내 as-of 복원 — 핵심 기여 (`+50.37`점)

공식 `asof_*_n`이 시즌을 넘어 연속 누적됨(다음 시즌 최소값 = 이전 최대값 `+1`,
예외 `0.0%`)을 이용해, 학습 시점에 고정한 2024년 말 상태를 빼면 각 선수의
**당해 시즌 한정 성적**이 정확히 복원된다.

```
시즌내 투구 수 = asof_pitcher_n(행) - anchor_n(투수)
시즌내 성공 수 = asof_pitcher_n(행) * asof_pitcher_success_rate(행) - anchor_sum(투수)
시즌내 성공률  = (시즌내 성공 수 + prior * k) / (시즌내 투구 수 + k)
```

| 상수 | 값 | 적용 위치 |
|---|---:|---|
| 피처 shrinkage `k` | `20` | Form 모델 피처 18개 (V102–V104에서 내부 최적 확인) |
| 드리프트 shrinkage | `3` | post-hoc 항 (V106) |
| 드리프트 신뢰도 스케일 | `150` | `n / (n + 150)` |
| 드리프트 가중치 | `0.10` | 보정 이후 적용 |

드리프트 항을 제거하면 월별 블록 승률이 `100% → 70%`로 무너진다. 트리는 `season`이
학습 범위 밖인 2025를 외삽하지 못하므로, 이 전역 항이 리그 수준 이동을 담당한다.

## 6. 규정 준수

| 규정 | 준수 방식 |
|---|---|
| 공식 데이터만 사용 | `train.csv`, `trackman_history.csv`만 사용. 외부 데이터·API 없음 |
| 사전학습 모델 | 사용하지 않음 |
| 각 테스트 행 독립 추론 | **실측 통과.** 1행씩 추론과 일괄 추론의 최대 절대차 `0.0` |
| 테스트 행 간 집계·빈도·분포·rolling·TE 금지 | 모든 lookup과 anchor는 학습 시점 고정. 입력은 각 행 자신의 공식 피처뿐 |
| 평가 데이터 분포 기반 사후 보정 금지 | 가중치·상수·prior 전부 학습 데이터에서 사전 확정 |
| 현재 투구 이후 정보 금지 | `asof_*`는 정의상 투구 직전 값. 복원은 두 as-of 상태의 차이이며 anchor에 마지막 행 결과를 쓰지 않음 |
| 현재 투구 위치·판정·구종·Trackman 금지 | 사용하지 않음 |
| 2025 Trackman 금지 | 2019–2024만 사용 |
| 선수 ID를 수치 크기로 해석 금지 | lookup 키로만 사용 |
| 고정 시드·버전 기록 | `random_state=42`, 2절에 버전 기재 |
