## 📋 sample_submission.csv

> 제출 형식 기준 파일 — **이 형식 그대로 제출해야 함**

```csv
row_id,control_success
TEST_000001,0.5
TEST_000017,0.5
TEST_000213,0.5
TEST_005332,0.5
TEST_035185,0.5
```

- `row_id`: test.csv의 row_id와 1:1 매칭 필수
- `control_success`: **0.0 ~ 1.0 사이의 확률값** (0.5는 기본값/baseline)
- 형식: CSV → ZIP 압축 후 리더보드 업로드

## ⚠️ 샘플 데이터에서 발견한 주요 특이사항

### 1. Cold-start 문제 (결측값 행 존재)

| row_id | 결측 이유 | 영향 컬럼 |
|--------|----------|---------|
| TEST_000017 | `asof_pitcher_prev*` 없음 → 최근 경기 이력 없는 신규/복귀 투수 | prev1/3/5 관련 6개 |
| TEST_005332 | `asof_pitcher_n = 0` → **이 투수의 기록이 전혀 없음** | 투수 관련 통계 전체 |
| TEST_000213 | `asof_batter_n = 0` → **이 타자의 기록이 전혀 없음** | 타자 관련 통계 전체 |
| TEST_035185 | `asof_batter_n = 0` + prev 없음 | 타자 통계 + prev 전체 |

> 💡 **모델링 핵심 과제**: `n=0` 또는 결측인 경우 어떻게 대체할 것인가?  
> → 리그 평균으로 대체(Smoothing), 별도 cold-start 피처 추가, 계층적 fallback 등 전략 필요

### 2. `game_type = R` (정규 시즌)
- 5건 모두 정규 시즌(Regular) 데이터
- 플레이오프/시범경기 등 다른 유형도 train에 포함되어 있을 수 있음

### 3. `li` (레버리지 인덱스) 범위
- `0.34` (낮은 압박) ~ `1.29` (높은 압박)
- `li > 1.0` = 평균보다 중요한 상황 → 제구 불안 가능성 검토 필요

### 4. `base_state` 표현 방식
- `___` = 주자 없음
- `1__` = 1루 주자만
- 형식: `123` 자리에 주자 유/무 (`_`는 비어있음, 숫자는 해당 베이스 주자 있음)
