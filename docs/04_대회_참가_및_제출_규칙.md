# 대회 참가 및 제출 규칙

> LG Aimers 온라인 해커톤(Phase 2) 참가·모델링·제출 시 준수해야 할 규칙을 정리한 문서입니다.
> 규칙 해석이 애매하거나 공지 내용이 변경된 경우에는 DACON의 최신 공식 공지와 운영진 답변을 우선합니다.

---

## 1. 개인 또는 팀 참여 규칙

- 개인 또는 팀으로 참여할 수 있습니다.
- 개인 참가자는 별도의 팀 신청 없이 `제출` 탭에서 자유롭게 제출할 수 있습니다.
- 팀 참가 및 팀 병합 정책은 대회 페이지의 `팀` 탭에서 확인합니다.
- 팀 구성 방법은 팀 페이지의 안내를 따릅니다.
- 팀은 최대 5명까지 구성할 수 있습니다.
- 동일인이 개인 참가와 팀 참가에 동시에 등록하거나, 여러 팀에 중복 등록할 수 없습니다.

---

## 2. 대회 규칙

### 2.1 사전학습 모델 및 가중치

다음 조건을 모두 만족하는 모델과 가중치만 사용할 수 있습니다.

- 공식적으로 누구에게나 가중치가 공개되어 있어야 합니다.
- 최소한 비상업적 이용이 허용되는 라이선스로 배포되어야 합니다.
- 위 조건을 만족하지 않는 모델 및 가중치는 사용할 수 없습니다.

사전학습 모델을 사용할 경우 재현과 검증을 위해 모델명, 정확한 가중치 버전, 출처, 라이선스를 기록합니다.

### 2.2 외부 API 사용 제한

- OpenAI API, Gemini API 등 원격 서버의 API로만 접근 가능한 모델은 사용할 수 없습니다.
- 학습, 전처리, 추론을 포함한 모든 작업은 로컬 환경에서 코드로 직접 실행하고 재현할 수 있어야 합니다.
- 실행 과정이 외부 서버의 응답에 의존해서는 안 됩니다.

### 2.3 외부 데이터 사용 금지

- 온라인 해커톤(Phase 2)에서 주최 측이 제공한 공식 데이터만 사용할 수 있습니다.
- 그 밖의 외부 데이터는 사용할 수 없습니다.

### 2.4 평가 데이터 예측 원칙

- `test.csv`의 각 행은 서로 독립적인 예측 대상입니다.
- 각 행의 예측에는 해당 행의 입력 변수와 주최 측이 제공한 공식 학습 데이터만 사용할 수 있습니다.
- 평가 데이터의 다른 행이나 평가 데이터 전체의 분포를 이용하여 특정 행의 예측값을 생성하거나 보정해서는 안 됩니다.

따라서 테스트셋 전체 통계, 테스트 행 간 순위, 테스트 배치의 분포 등에 의존하는 전처리와 후처리는 사용하지 않습니다.

## 3. 코드 및 PPT 제출 규칙

온라인 해커톤(Phase 2) 종료 후 오프라인 해커톤(Phase 3) 진출을 희망하는 팀은 지정된 기한 내에 아래 자료를 `dacon@dacon.io`로 제출해야 합니다.

- 코드 파일 확장자: `.py` 또는 `.ipynb`
- 코드와 주석 인코딩: UTF-8

### 필수 제출 자료

- 학습 코드의 개발 환경: OS 및 라이브러리 버전
- Private Score 재현용 학습 코드
  - 추론 코드는 리더보드에 제출한 추론 코드로 대체됩니다.
- 자유 형식의 솔루션 PPT
- 모든 팀원의 오프라인 해커톤(Phase 3) 참가 여부

Phase 3 진출을 희망한다고 해서 자동으로 진출하는 것은 아닙니다. 코드 및 PPT 제출과 검증을 모두 통과한 Private 리더보드 상위 팀을 기준으로 약 100명이 진출합니다.

---

## 4. 유의 사항

- 일일 최대 제출 횟수는 5회입니다.
- 사용 가능 언어는 Python입니다.
- 대회 직후 공개되는 Private 리더보드 순위는 Phase 2 최종 순위가 아닙니다.
- 코드 검증을 거친 뒤 Phase 3 진출자가 결정됩니다.
- 코드 제출 기능을 악용한 평가 데이터셋 유출 등 규칙 위반이 발견되면 실격될 수 있습니다.
- 평가 서버의 시스템 부하와 스케줄링에 따라 동일한 추론 코드와 모델도 제출 시점별 추론 속도가 달라질 수 있습니다.
- 평가 서버에서 실제로 측정·기록된 리더보드 점수만 공식 결과로 인정됩니다.
- DACON은 부정 제출을 금지하며, 부정 제출 이력이 있는 경우 평가가 제한될 수 있습니다.
- 부정 제출 관련 공지: <https://dacon.io/notice/notice/13>

- 예시: `[DACON 답변 요청] 시상식은 언제 열리나요?`

## 실무 준수 체크리스트

- [ ] 사용하는 데이터가 모두 Phase 2 공식 제공 데이터인지 확인
- [ ] 외부 API 호출이 학습·전처리·추론 코드에 없는지 확인
- [ ] 사전학습 모델의 공개 여부와 라이선스 확인 및 기록
- [ ] 테스트셋 전체 또는 다른 테스트 행의 정보에 의존하는 로직 제거
- [ ] 고정 시드, OS, Python 및 라이브러리 버전 기록
- [ ] 깨끗한 환경에서 학습 및 Private Score 재현 절차 점검
- [ ] 제출 코드와 주석을 UTF-8로 저장
- [ ] 솔루션 PPT와 팀원별 Phase 3 참가 여부 준비
- [ ] 일일 제출 횟수 5회 이내인지 확인

## 6. 팀 제출 파일 운영 규칙

### 단일 작업 위치

- 실제 업로드할 파일은 모두 `submissions/by_submitter/` 아래에서 관리합니다.
- 루트 디렉토리나 `submissions/` 바로 아래에 남은 과거 ZIP은 제출 대상으로 간주하지 않습니다.
- 각 제출자의 폴더에는 업로드할 파일을 반드시 `submit.zip`이라는 이름으로 둡니다.

### 현재 담당

| 제출자 | 작업 폴더 | 현재 실험 |
| --- | --- | --- |
| 전병윤 | `전병윤_RF_기준선/` | 공식 RandomForest 기준선 |
| 이준형 | `이준형_안정형/` | ExtraTrees 70% + HistGBDT 30% |
| 오현기 | `오현기_보정형/` | 검증 기반 affine 앙상블 |

### 새 제출 생성 절차

1. 공식 제공 데이터만 사용했는지 확인합니다.
2. 시간순 홀드아웃 성능과 모델 설정을 담당 폴더의 `설명.md`에 기록합니다.
3. 실제 평가 서버와 동일한 상대경로에서 추론 스모크 테스트를 수행합니다.
4. ZIP 내부에 데이터셋, 임시 출력, 캐시, API 키가 없는지 확인합니다.
5. `unzip -t submit.zip`으로 압축 무결성을 확인합니다.
6. 검증된 ZIP으로 담당 폴더의 `submit.zip`을 교체합니다.
7. 담당자는 이 파일을 수정·재압축하지 않고 그대로 업로드합니다.
8. 제출 후 `submissions/by_submitter/README.md`에 점수와 시각을 기록합니다.

동일 모델을 여러 명이 중복 제출하지 않습니다. 모델 배정을 변경할 때는 배정표와
각 `설명.md`를 먼저 수정해 제출 이력이 뒤섞이지 않게 합니다. 일일 제출 횟수와
팀 구성 전 개인 제출 의무는 DACON 대회 페이지의 최신 공지를 최우선으로 따릅니다.
